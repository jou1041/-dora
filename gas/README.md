# 結帳系統 × Google 試算表（Google Apps Script）

網站結帳 → 送到 Apps Script → 驗證、重新計價、編號 → 寫進 Google 試算表 → 寄通知信。

```
顧客下單 (index.html)
   │  fetch POST (JSON，text/plain 免 CORS 預檢)
   ▼
Apps Script Web App (gas/Code.gs)
   ├─ 驗證欄位、防機器人、頻率限制、客戶端代碼去重
   ├─ 以「商品」工作表重新計價（不信任網頁傳來的金額）
   ├─ LockService 鎖定 → 產生訂單編號 JH + yyMMdd + 4 碼流水號
   ├─ 寫入「訂單」「訂單明細」
   └─ 寄店家通知信／顧客確認信
試算表
   ├─ 改「狀態」欄 → 自動寄信通知顧客（製作中／可取餐／已出貨／已取消）
   └─ 每天固定時間寄營業摘要給店家
```

## 一、部署步驟（約 10 分鐘）

1. **建立試算表**：到 Google 雲端硬碟新增一個空白試算表，取名「煎和鍋貼所｜訂單」。
2. **開啟 Apps Script**：試算表上方選單 `擴充功能 → Apps Script`。
3. **貼上程式**：把 `gas/Code.gs` 的內容整個貼進編輯器（取代預設的 `myFunction`）。
   - 左側 `專案設定` 勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，回到編輯器把 `gas/appsscript.json` 內容貼進去。
4. **設定**：修改檔案最上方 `CONFIG`
   - `NOTIFY_EMAILS`：店家收新訂單通知的信箱（可填多個，逗號分隔；留空就不寄）。
   - `SHIPPING_FEE`、`FREE_SHIP`：需與網站 `index.html` 內的數字一致（目前 150／1500）。
5. **初始化**：存檔後，重新整理試算表，出現選單 `鍋貼系統 → 初始化工作表`，執行並完成授權。
   - 會建立 `訂單`、`訂單明細`、`商品` 三張表（`系統記錄` 會在出錯時自動建立）、狀態下拉選單與顏色，並安裝「狀態通知」「每日摘要」兩個觸發器。
6. **部署成網頁應用程式**：右上角 `部署 → 新增部署作業 → 類型：網頁應用程式`
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 部署後複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。
7. **貼回網站**：打開 `index.html`，找到
   ```html
   <script>window.JIANHE_CONFIG = window.JIANHE_CONFIG || { orderApi: '' };</script>
   ```
   把網址貼進 `orderApi: '…'`，存檔、推上 GitHub。
   （`orderApi` 留空時網站是「示範模式」，下單成功畫面照常顯示，但不會寫入試算表。）
8. **測試**：在網站實際下一筆單，確認試算表出現資料；也可用瀏覽器直接開網址，看到 `{"ok":true,…}` 代表服務正常。

> 之後只要修改 `Code.gs`，需到 `部署 → 管理部署作業 → 編輯 → 版本：新版本` 才會生效，網址不會變。

## 二、試算表欄位

| 工作表 | 內容 |
|---|---|
| 訂單 | 一張訂單一列：時間、編號、**狀態**、取餐方式、顧客資料、商品摘要、金額、付款方式、備註…（最後一欄「客戶端代碼」預設隱藏，用來防重複送單） |
| 訂單明細 | 一個品項一列，方便做銷售統計與樞紐分析 |
| 商品 | 品項ID、分類、品名、單位、**單價**、**上架**（勾選才能被訂購） |
| 系統記錄 | 錯誤與寄信失敗的紀錄 |

**狀態**欄是下拉選單：新訂單 → 製作中 → 可取餐／已出貨 → 已完成（或已取消）。改成「製作中／可取餐／已出貨／已取消」時，若顧客有填 Email 會自動收到通知。

## 三、價格要改在哪裡？

伺服器以「商品」工作表的單價為準重新計算總額，所以**調整價格時，網站 `index.html` 與「商品」工作表要一起改**，否則顧客在網頁看到的金額與伺服器計算的不同（顧客成功畫面顯示的是伺服器算出的金額）。
商品暫停供應：把「商品」工作表的「上架」取消勾選即可（網站仍會顯示，但下單時會提示該商品無法訂購）。

## 四、安全與限制

- Web App 網址是公開的，所以做了：欄位驗證、隱藏欄位防機器人、同一支電話 10 分鐘最多 5 筆、金額由伺服器重算、寫入前處理 `= + - @` 開頭的內容避免試算表公式注入。
- 同一客戶端代碼只會建立一筆訂單；網路逾時時顧客重按送出不會重複下單。
- `MailApp` 每日寄信額度：一般 Gmail 帳號約 100 封、Google Workspace 約 1500 封。
- 訂單查詢：`網址?action=status&id=訂單編號&phone=手機號碼` 會回傳狀態（需編號與電話都符合）。
- 付款方式目前只記錄顧客選擇，並未串接金流；LINE Pay／信用卡需另外接金流 API。
